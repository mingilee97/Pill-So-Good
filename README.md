# 1. 데이터 전처리 및 탐색

## 1-1. 문제 해결에 필요한 데이터를 적절히 수집하였나요?

### 시작 데이터의 한계

주어진 데이터는 **56종 · 사진 221장**뿐. 

```
          (맞히는 종류 수) × (그 종류들의 평균 AP)
 mAP  =  ────────────────────────────────────────
                test에 등장하는 전체 종류 수
```

mAP는 *평균낸*정답에 등장하는 종류를 기준으로** 다. 우리가 답하지 못한 종류는 AP가 `0`이고,
그 0도 평균에 포함된다. 즉 **아는 알약을 아무리 완벽히 맞혀도, 모르는 알약 수만큼 깎인다.**

```
우리 종류를 완벽(AP 0.98)하게 맞혀도
  56종 커버 / 100종 존재  →  천장 0.549
  93종 커버 / 100종 존재  →  천장 0.911
```

**따라서 수집의 목표를 "양"이 아니라 "종류 수"로 잡았다.**

v = (v - v.mean()) / (v.std() + 1e-8)      # 밝기·대비 차이를 지운다
sim = M_test @ M_hub.T / M_hub.shape[1]    # 전부 대 전부 코사인 유사도

**v4 재구축에서 211장 제거** (캐글 test와 257쌍 일치).
이걸 걸러내지 않으면 시험 문제를 외운 셈이라 내부 점수만 부풀고 실제로는 반칙이다.

**③ 그룹 분할** — 같은 장면이 train/val에 걸치지 않게

같은 알약 조합을 **각도만 바꿔 3장**씩 찍었다. 무작위로 나누면 거의 같은 사진이
train과 val에 동시에 들어가 검증 점수가 실력이 아니라 기억력을 재게 된다.

```
비슷한 사진끼리 Union-Find로 묶어 그룹 통째로 배정
조합 4,062개  →  그룹 2,895개   (1,167곳을 이어붙임)

검증: 두 split에 걸친 그룹 0개
```

**④ 조각 오리기** — 상자 + 여백 10%

```python
cx, cy = r.x + r.w/2, r.y + r.h/2          # 상자 중심
w, h = r.w * 1.10, r.h * 1.10              # 여백 10%
```

여백을 두는 이유는 검출기가 그린 상자가 정답보다 살짝 작을 때 알약이 잘리지 않게 하기 위함이다.
**학습과 추론에 동일한 값을 적용**했다.

**⑤ 정규화** — ImageNet 통계 사용 (사전학습 가중치와 조건을 맞추기 위해)

# 2. 모델 선정 및 설계

## 2-1. 적절한 딥러닝 모델을 선택하고 설계하였나요?

### 최종 아키텍처

```
사진 (976×1280)
   │
   ├─▶ [1단계] YOLO11s 검출기 1개        "알약이 어디 있나"   1종만 구분
   │
   ├─▶ 조각 오리기 (상자 + 여백 10%)
   │
   ├─▶ [2단계] ResNet18 분류기 9개       "무슨 약인가"       118종
   │
   └─▶ 확률 9장을 평균 → 제출 파일
```

| 구성 요소 | 선택 | 규모 |
|---|---|---|
| 검출기 | YOLO11s | 9.4M 파라미터 · imgsz 416 · 클래스 1개 |
| 분류기 | ResNet18 × 9 | 각 11.2M 파라미터 · 입력 224 또는 384 |
| 결합 | 확률 산술평균 | 상자는 공유, 분류 확률만 평균 |

## 2-2. 모델 설계와 선택 이유를 명확히 설명하고 있나요?

### 결정 1 — 왜 2단계인가 (검출과 분류의 분리)

두 갈래를 실제로 비교했다.

```
갈래 A — 한 번에
  사진 ──▶ [YOLO: 상자 + 118종 동시에] ──▶ 답

갈래 B — 두 번에  (채택)
  사진 ──▶ [YOLO: "알약이다" 1종만] ──▶ 조각 ──▶ [ResNet18: 118종] ──▶ 답
```

| 실험 | 조건 | 결과 |
|---|---|---|
| 갈래 A 1차 | 93종 · 사진 4,522장 | −0.0096 |
| 갈래 A 2차 | 118종 · 사진 11,713장 (데이터 2.6배) | 0.60448 (−0.0163) |

**두 번 다 밀렸다.** 검출기에게 "찾기"와 "구분하기"를 동시에 시키면 둘 다 어중간해진다.
분리하면 검출기는 "알약처럼 생긴 것" 하나만 잘 찾으면 되고,
분류기는 이미 오려진 깨끗한 조각만 보면 된다.

### 결정 2 — 왜 YOLO11s이고 왜 imgsz 416인가

검출 대상이 **단일 클래스**라 큰 모델이 필요하지 않았다. 해상도는 실험으로 결정했다.

| 검출 해상도 | 점수 | 평균 상자 크기 | 평균 확신 |
|---|---|---|---|
| **416 (학습 해상도)** | **0.62316** | 257.6 × 286.5 | 0.940 |
| 640 | 0.57300 | 257.2 × 288.0 | 0.939 |
| 960 | 0.29187 | 215.4 × 243.9 | 0.762 |

**추론 해상도를 학습 해상도에서 벗어나게 하면 무너진다.**
640은 평균 상자 크기가 0.4px밖에 안 변했는데도 −0.050이었다.
평균이 같다고 개별 상자가 같은 것이 아니다.

### 결정 3 — 왜 ResNet18인가 (더 큰 모델을 쓰지 않은 이유)

더 깊거나 다른 계열의 모델을 실제로 학습시켜 비교했다.

| 뼈대 | 파라미터 | 검증 균형 정확도 | 앙상블 기여 |
|---|---|---|---|
| **ResNet18** | 11.2M | 0.9965 | 기준 |
| ResNet50 | 23.5M | 0.9963 | −0.0008 |
| EfficientNet-B0 | 4.0M | 0.9965 | −0.0042 |

**더 큰 모델이 더 낫지 않았다.** 그리고 결정적으로, 세 뼈대의 **판단 일치율이 97.6~98.7%**였다.
구조를 바꿔도 같은 답을 내므로 굳이 무거운 모델을 쓸 이유가 없었다.

### 결정 4 — 왜 분류기를 9개나 쓰는가 (앙상블 설계)

단일 모델의 개선 폭이 한계에 부딪힌 뒤(최고 0.62464), 학습 없이 점수를 올릴 방법으로 앙상블을 택했다.

```
모델 A: 005000을 22074로 착각     22074  0.70
모델 B: 005000으로 맞힘           005000 0.60
모델 C: 005000으로 맞힘           005000 0.50
────────────────────────────────────────────
평균                              005000 0.37  >  22074 0.23
```

**투표가 아니라 확률의 평균**이라, 확신 있는 소수가 우물쭈물한 다수를 이길 수 있다.

**상자를 공유하는 설계가 핵심이다.** 검출은 한 번만 하고 아홉 분류기가 같은 조각을 본다.
상자까지 서로 달랐다면 "어느 상자가 맞나"부터 정해야 하는데, 그 방식(WBF)은
상자가 뭉개져 고IoU 구간을 잃어 −0.0081로 실패했다.

### 교재가 정확히 무엇이었나 — 네 가지 축

**축 1. 학습 데이터 — v3인가 v4인가**

| | 사진 | 상자 | 조합(장면) | 차이 |
|---|---|---|---|---|
| v3 | 8,898장 | 34,314 | 3,085 | 확보한 zip 전체를 훑어 118종을 채운 상태 |
| v4 | 11,713장 | 44,818 | 4,062 | 여기에 TS_4·TS_8을 더해 **취약 종류를 보강** |

종류 수는 둘 다 118종으로 같다. 달라진 것은 **종류별 장면 다양성**이다.

```
016235 카듀엣정     v3에서 조각  38개  →  v4에서 440개   11.6배
005000 비유피-4정   v3에서 조각  21개  →  v4에서 194개    9.2배

학습 조각 100개 미만 종류   v3에서 23종  →  v4에서 6종
```

같은 알약을 v3 모델은 7개 장면으로, v4 모델은 96개 장면으로 배웠다.
**같은 과목을 얇은 교재로 본 학생과 두꺼운 교재로 본 학생의 차이다.**

**축 2. 크롭 크기 — 224인가 384인가**

오려낸 알약 조각을 몇 픽셀로 줄여서 넣느냐다.

```
224 × 224   조각을 작게 봄 — 모양·색 위주로 판단, 학습이 빠름
384 × 384   조각을 크게 봄 — 각인·표면 질감까지 보이지만 학습이 3배 느림
```

**같은 알약을 돋보기 없이 본 것과 돋보기로 본 것의 차이다.**

**축 3. 증강 세기 — 약한가 강한가**

증강은 **한 장의 사진을 매번 조금씩 다르게 만들어 보여주는 것**이다.
사진을 외우지 않고 알약을 배우게 하려는 장치다.

| | 224 계열 4개 | 384 계열 5개 |
|---|---|---|
| 180도 회전 | O | O |
| 색 흔들기 | ±25% | **±35%** |
| 흐리게 | O | O |
| 자르기·확대 | — | **O** |
| 기울이기·이동 | — | **O** |
| 일부 지우기 | — | **O** |

강한 증강은 **알약의 일부를 지우고, 기울이고, 잘라서** 보여준다.
한 가지 단서(예: 각인)에 의존하지 못하게 만드는 것이 목적이다. 자세한 내용은 3-1절에 있다.

**축 4. 전처리 — 조각을 손보고 넣는가**

```
없음      오려낸 그대로 (7개 모델)
bright    사진 전체 밝기를 같은 배율로 맞춤 — 조명 차이를 지운다
clahe     LAB의 밝기 채널에만 국소 대비를 키움 — 각인이 도드라진다
```

**같은 교재를 형광펜으로 다르게 칠해 읽은 셈이다.**
개별 성적은 둘 다 낮았지만(0.62367 · 0.61604), 다르게 틀리기 때문에 팀에 남았다.

---

4~7번은 **한 번의 학습에서 10·20·30·40 에포크 지점을 저장한 것**이다.
같은 뿌리인데도 기여하는 이유는, 강한 증강 때문에 에포크마다 다른 방향으로 흔들려
**우연히 서로 다른 실수를 하게 됐기** 때문이다.

### 정말 다른 모델인가 — 세 가지 확인

**① 가중치 숫자가 다르다**

```
층 하나(layer1.0.conv1)의 실제 값 앞 5개

전체 1,124만 개 숫자의 평균 차이
  v3_224 vs v4_224   0.000868      (완전히 같다면 0.000000)
  v3_224 vs clahe    0.000820
```

**② 판단이 실제로 갈린다**

| 비교 | 판단이 다른 상자 |
|---|---|

같은 모델을 아홉 번 돌린 것이라면 **전부 0개**여야 한다. 추론은 결정적이기 때문이다.
31~94개씩 갈리므로, 평균낼 가치가 생긴다.

**③ 앙상블이 실제로 일하는 순간**

전체 3,433개 상자 중 **47개**에서 9개 중 5개 이하만 동의했다. 그중 하나를 보면—

```
[1069.png · 상자 194]

v3_224      33208   확신 0.09
v3_384e30    6563   확신 0.44   ←
v4_224       3544   확신 0.09
v4_384e20    6563   확신 0.96   ←
v4_384e30   10221   확신 0.57
v4_384e40    6563   확신 0.79   ←
v4_384e10   29345   확신 0.37

clahe       22347   확신 0.11
──────────────────────────────────
최종답  6563 (조인스정 200mg)   동의 3/9
```

아홉이 여섯 갈래로 흩어졌고, 이긴 답은 **3표뿐**이었다.
그런데도 이긴 이유는 확신이 0.44·0.96·0.79로 강했기 때문이다.
나머지는 0.09·0.11처럼 "잘 모르겠다"에 가까웠다.

> **확신 있는 소수가 우물쭈물한 다수를 이긴다.**
> 이것이 단순 다수결이 아니라 확률을 평균내는 이유다.

덧붙여, 여기서 이긴 `6563 조인스정`은 특징 벡터 분석에서
**"이웃이 19% 다르다고 말하는" 의심 목록 2위**에 오른 종류다.
어려운 자리에서 앙상블이 실제로 작동하고 있다.

### 왜 하필 9개인가 — 조합을 실제로 시험했다

확률 행렬을 파일로 저장해두면 조합을 바꿔 제출 파일을 만드는 데 몇 초면 된다.
이를 이용해 여러 조합을 실제로 제출했다.

```
6개  →  9개    +0.0079   ✅  실패작(bright·clahe)과 v4_384e10을 추가
9개  →  11개   −0.0003       배경 제거·종횡비 보존 모델 추가
9개  →  10개   −0.0008       ResNet50 추가
9개  →  10개   −0.0042       EfficientNet 추가
9개  →  10개    0.0000       갈래 A 추가 (결과 파일이 완전히 동일)
```

**9개가 정점이고, 그 뒤로는 무엇을 넣어도 내려간다.**

### 왜 성적 나쁜 모델을 남겼나

`clahe`는 단독 0.61604로 9개 중 꼴찌다. 개별로만 보면 명백한 실패작이다.
그런데 **빼면 점수가 떨어진다.**

반대 사례도 있다. `bgmask`(배경 제거)는 0.61054로 `clahe`와 단독 점수가 0.005밖에 차이 안 나는데,
팀에 넣으면 오히려 손해다.

| 모델 | 단독 점수 | 앙상블 기여 |
|---|---|---|
| `clahe` | 0.61604 | **포함 (빼면 하락)** |
| `bgmask` | 0.61054 | 제외 (넣으면 −0.0003) |
| `lbox` | 0.60702 | 제외 |

> **개별 성적으로는 팀 기여를 예측할 수 없었다.**
> 실제로 성적 좋은 3개만 모은 조합(0.61925)이 실패작 포함 9개(0.63420)보다 0.015 낮았다.
> 앙상블에서 중요한 것은 개별 성능이 아니라 **다르게 틀리는 성질**이다.

## 3-1. 적절한 하이퍼파라미터 튜닝을 수행하였나요?

### 최종 하이퍼파라미터

| 항목 | 값 | 선정 근거 |
|---|---|---|
| 옵티마이저 | SGD (momentum 0.9, wd 5e-4) | 안정적 수렴 |
| 학습률 | 0.005 (224) / 0.01 (384) | 강한 증강 계열은 더 높게 |
| 스케줄러 | StepLR(5, 0.5) / CosineAnnealing(T=100) | 짧은 학습 / 긴 학습 |
| 배치 | 64 | MPS 메모리 한계 내 최대 |
| 에포크 | 12 (224) / 30 (384) | 아래 실험 참조 |
| 손실 | CrossEntropy + label_smoothing 0.05 | 과잉 확신 억제 |
| 크롭 크기 | 224 / 384 | 아래 실험 참조 |
| 검출 해상도 | 416 | 640·960에서 폭락 확인 |
| 여백 | 10% | 학습·추론 동일 |
| 표집 | WeightedRandomSampler (1/개수) | 종류 불균형 보정 |
| 클리핑 | grad norm 10.0 | 발산 방지 |

### 크롭 크기와 에포크 — 단독으로 바꾸면 손해였다

```
384 크롭만 바꿈                  −0.0041
384 + 강한 증강 + 30에포크        +0.0015   ← 단독 최고 기록
```

**세 가지가 세트로 묶여야 효과가 났다.** 증강이 세면 매번 다른 모습이 나오므로
그만큼 오래 배워야 하고, 잘라내고 가려도 정보가 남으려면 조각이 커야 한다.

### 에포크 수 — 100에포크 학습에서 4개 지점을 제출해 확인

| 에포크 | 점수 |
|---|---|
| 10 | 0.62114 |
| **30** | **0.62464** |
| 40 | 0.62103 |

**30이 정점이고 40은 다시 떨어진다.** 더 오래 학습하면 우리 데이터에만 특화되어 손해였다.

> **주의**: 코사인 감쇠 기준을 100에포크로 두었으므로,
> `EPOCHS=40`으로 줄여 적으면 같은 ep30이라도 학습률 궤적이 달라진다.
> 스케줄 기준은 100으로 유지하고 중간 지점을 저장하는 방식을 썼다.

### 증강 — 두 세기를 설계했다

| | 224 계열 4개 | 384 계열 5개 |
|---|---|---|
| 180도 회전 | O | O |
| 색 흔들기 | ±25% | **±35%** |
| 흐리게 | O | O |
| 자르기·확대 | — | **O** |
| 기울이기·이동 | — | **O** |
| 일부 지우기 | — | **O** |

```python
# 강한 증강 (384 계열)
T.RandomApply([T.RandomRotation((180,180))], p=0.5)          # 뒤집어도 같은 약
T.RandomResizedCrop(384, scale=(0.65,1.0), ratio=(0.85,1.18))  # 65~100%만 잘라 확대
T.RandomAffine(degrees=10, translate=(0.05,0.05))           # 상자가 어긋나도 버티게
T.ColorJitter(brightness=0.35, contrast=0.35,
              saturation=0.20, hue=0.03)                    # hue만 작게 — 색이 핵심 단서

```

**`hue=0.03`으로 색조만 유독 작게 둔 것**이 의도적 선택이다.
알약 색깔은 종류를 가르는 핵심 단서라, 많이 흔들면 흰 약과 노란 약을 헷갈리게 된다.

**`RandomErasing`은 한 가지 단서에 의존하지 못하게 하는 장치다.**
가리지 않으면 "각인이 ABC네" 하나만 보고 판단하는 버릇이 들지만,
가리면 각인이 안 보일 때 모양·색·크기도 함께 보게 된다.

|---|---|---|

| label_smoothing 값 | 0.05 고정 | 상동 |
| BatchNorm 통계 재추정 | 시도 후 폐기 | −0.0059 (3-3절) |

## 3-2. 성능을 적절한 평가 지표로 평가하였나요?

### 평가 지표 — 캐글 채점기를 직접 구현했다

대회 지표는 `mAP@0.75:0.95`다.

```
IoU 문턱  0.75  0.80  0.85  0.90  0.95   다섯 구간에서 각각 채점
                          ↓
                 다섯 점수의 평균  =  AP
                          ↓
      정답에 존재하는 모든 종류의 AP를 평균  =  mAP
```

문턱이 0.5가 아니라 0.75부터라, **상자가 웬만큼 맞아서는 뒤쪽 구간을 통째로 잃는다.**

```
100픽셀 상자 기준
  완벽        IoU 1.000   0.75:O 0.85:O 0.95:O
  5px 밀림    IoU 0.822   0.75:O 0.85:X 0.95:X
  10px 밀림   IoU 0.681   0.75:X 0.85:X 0.95:X
```

### 지표를 직접 구현해 병목을 분해했다

내부 검증 데이터를 캐글과 같은 규칙으로 채점하고, **부품을 하나씩 정답으로 바꿔치기**했다.

| 시나리오 | mAP | 개선폭 | 해석 |
|---|---|---|---|
| ① 우리 파이프라인 그대로 | 0.9780 | — | 실제 실력 |
| ② 상자만 정답으로 | 0.9933 | +0.0153 | 검출을 완벽히 해도 이만큼뿐 |
| ③ 종류만 정답으로 | 0.9835 | +0.0055 | 분류를 완벽히 해도 이만큼뿐 |
| ④ 둘 다 정답 | 1.0000 | — | **채점기 검산 통과** |

**④를 넣은 이유**: 1.0이 안 나오면 채점기가 틀린 것이고, 그러면 ①②③ 숫자도 믿을 수 없다.
측정 도구를 먼저 검산하는 것이 측정의 첫 단계다.

### 보조 지표 — 균형 정확도

종류별 데이터가 불균형하므로 단순 정확도는 다수 종류에 끌려간다.
**종류별 정확도를 먼저 구하고 그 평균**을 취했다.

```python
per = collections.defaultdict(lambda: [0, 0])       # 종류별 [맞은 수, 전체]
for t, q in zip(정답, 예측):
    per[t][1] += 1
    per[t][0] += int(t == q)
bal = float(np.mean([a/b for a, b in per.values()]))  # 종류별 정확도의 평균
```

### 검증 설계의 한계를 확인하고 명시했다

**내부 지표는 끝까지 캐글을 예측하지 못했다.**

```
검증 균형 정확도   0.9965
검증 mAP          0.9780
캐글              0.6342
```

세 가지 검증 설계(그룹 분할, 홀드아웃 2회)를 시도했지만 **단 한 번도 캐글 순위를 맞히지 못했다.**
train과 val이 같은 촬영 환경에서 나왔기 때문이다. 그래서 **모든 판단을 실제 제출로만** 내렸다.

| 이미 천장 | 4 | top-k, 장면 일관성, TTA, 사전확률 보정 |
| 모델 다양성 부족 | 3 | ResNet50, EfficientNet, 갈래 A |
| 정보를 지움 | 2 | 배경 제거, 종횡비 보존 |
| 환경이 다른 데이터 | 1 | 단일 알약 데이터 |

### 진단 실험 — 왜 안 오르는지를 측정으로 좁혔다

**① top-5 실험** — 상자마다 후보를 5개까지 넣었더니 `+0.0001`

| 상위 k | 덮는 종류 |
|---|---|
| 1 | 75 |
| 3 | 115 |
| **5** | **118** |

top-5는 이미 118종을 전부 덮고 있었다.
즉 우리는 그 종류를 "제안 안 한 게" 아니라 **제안한 자리가 틀렸다.**

**② 특징 벡터 분석(OOD)** — 분류층을 떼고 512차원 벡터로 이웃을 찾았다

```
test 조각이 학습 데이터와 닮은 정도   중앙값 0.987
1-NN이 앙상블과 같은 답              98.1%

가장 안 닮은 10% (344개)   NN 불일치 14.8%
나머지 90%                NN 불일치  0.4%      ← 37배 차이
```

여기서 처음으로 **구체적인 의심 목록**이 나왔다.

| 종류 | 예측 수 | 평균 닮음 | NN 불일치 |
|---|---|---|---|
| 22347 자누비아정 50mg | 80 | 0.959 | 21% |
| 6563 조인스정 200mg | 43 | 0.941 | 19% |
| 27926 울트라셋이알서방정 | 25 | 0.981 | 12% |
| 3544 무코스타정 | 175 | 0.916 | 9% |

**③ 앙상블 조합 실험** — 확률 행렬을 저장해 조합을 초 단위로 시험

| 구성 | 모델 수 | 점수 |
|---|---|---|
| 성적 좋은 3개만 | 3 | 0.61925 |
| 기본 6개 | 6 | 0.62632 |
| **실패작 포함 9개** | **9** | **0.63420** |
| 11개 | 11 | 0.63392 |
| 9개 + ResNet50 | 10 | 0.63345 |
| 9개 + EfficientNet | 10 | 0.63001 |

> **성적 좋은 모델만 골라 모으면 오히려 나빠진다.**
> 개별로 실패한 모델도 **다르게 틀리기만 하면** 팀에 기여한다.

### 마지막 실험이 밝힌 벽의 정체

앙상블 멤버 전부가 같은 상자를 본다는 게 한계라고 보고,
상자부터 다르게 그리는 **갈래 A**를 118종으로 재학습해 13번째 투표자로 넣었다.

```
갈래 A vs 최고 조합의 일치율     99.9%
2단계 모델끼리의 일치율          97 ~ 99%

앙상블 결과 파일에서 달라진 상자 = 0개
```

> **가장 다르게 만든 모델이 가장 똑같이 답했다.**
> 데이터·전처리·증강·크롭·뼈대·파이프라인 구조까지 전부 바꾼 모델 열넷이
> 똑같은 지점에서 똑같이 틀린다면, 그건 모델의 오차가 아니라
> **학습 데이터가 모델에게 그렇게 배우라고 시킨 결과**다.

# 5. 결과 해석 및 비즈니스 시사점

## 5-1. 결과를 비즈니스 관점에서 해석하고 시사점을 도출하였나요?

### 서비스 맥락

**Health Eat** — 사용자가 복용 중인 약을 사진으로 찍으면 자동으로 인식해
복약 기록을 관리하는 헬스케어 앱. 손으로 약 이름을 입력하는 번거로움을 없애는 것이 목적이다.

### 현재 성능이 서비스에서 뜻하는 것

```
mAP@0.75:0.95 = 0.634
```

| 지표 | 값 | 서비스 의미 |
|---|---|---|
| 알약 검출(위치 찾기) | 사진당 4.1개, 재현율 99.5% | **약을 놓치는 일은 거의 없다** |
| 학습 데이터와 유사한 알약 | 정확도 99% 수준 | 흔한 약은 신뢰할 만하다 |
| 커버 추정 | 약 78종 중 50종 | **5개 중 2개는 틀리게 이름을 댄다** |

**핵심 리스크**: 모델은 **모르는 약도 아는 약 중 하나로 자신 있게 답한다.**
평균 확신이 0.94인데 실제 정확도는 그보다 훨씬 낮다.
의료 영역에서 **"틀렸는데 확신하는 것"은 "모르겠다"보다 위험하다.**

### 서비스 적용 시 제언

| 단계 | 권고 |
|---|---|
| **지금 배포한다면** | 자동 기록이 아니라 **후보 제시 + 사용자 확인** 방식. 상위 3~5개를 보여주고 사용자가 고르게 한다 |
| **확신 임계값 운영** | 앙상블 9개가 만장일치가 아닌 3.6% 구간은 "확인 필요"로 분리 |
| **낯선 알약 감지** | 특징 벡터로 학습 데이터와의 거리를 재면, 낯선 10%에서 오류율이 37배 높다는 것을 확인했다. 이 신호로 "인식 불가"를 띄우는 게 틀린 답을 주는 것보다 낫다 |
| **단독 판독 금지** | 복약 알림·처방 대조 등 **의사결정에 직결되는 용도로는 현 성능으로 부적합** |

### 데이터 투자 관점의 시사점

이 프로젝트에서 가장 값어치 있는 발견은 **어디에 투자해야 하는지**에 대한 것이다.

```
모델 개선(뼈대·구조·전처리·증강)에 쓴 시간   약 40시간   →  합계 +0.01
종류 커버리지 확대                           약 8시간    →  +0.163
```

**모델을 바꾸는 축은 전부 막혔다.** 데이터·전처리·증강·크롭·뼈대·파이프라인 구조까지
전부 바꾼 모델 열넷이 **98~99.9% 같은 답**을 냈다.

> 실무 함의: **약품 인식 서비스의 성패는 모델링이 아니라 약품 DB의 커버리지에 달려 있다.**
> 국내 유통 경구약은 수천 종인데 우리는 118종을 다뤘다.
> 신규 약품이 계속 나오므로 **데이터 수집 파이프라인을 상시 운영하는 것**이
> 모델을 고도화하는 것보다 우선순위가 높다.

## 5-2. 결과가 초기 문제 정의와 목표를 잘 충족하고 있나요?

### 목표 대비 달성도

| 목표 | 달성 | 근거 |
|---|---|---|
| 사진에서 알약 위치 검출 | **충족** | 재현율 99.5%, 사진당 4.1개 검출 |
| 알약 종류 식별 | **부분 충족** | 학습된 종류는 정확, 미학습 종류는 오답 |
| 캐글 점수 향상 | **충족** | 0.42532 → 0.63420 (+49%) |
| 재현 가능한 파이프라인 | **충족** | 노트북 실행 7.4분, 결과 파일 일치 검증 완료 |

### 초기 문제 정의를 수정해야 했던 지점

프로젝트 초반에는 문제를 **"분류 정확도를 올리는 것"**으로 정의했다.
그러나 채점기를 직접 구현해 측정한 결과, 정의가 틀렸다는 것이 드러났다.

```
② 상자만 정답으로 바꾸면    +0.0153
③ 종류만 정답으로 바꾸면    +0.0055
```

**우리 데이터에서는 검출도 분류도 고칠 게 거의 없었다.** 진짜 문제는
**"우리가 아예 다루지 못하는 종류"**였고, 문제 정의를 그쪽으로 옮긴 뒤에야 큰 상승이 나왔다.

이 재정의가 만든 커버리지 공식은 사후 검증에서도 맞았다.

```
추정 천장  =  50종 × 0.98 ÷ 78종  =  0.628
실제 최종 점수                    =  0.634
```

**0.006 차이.** 남은 격차가 모델 성능이 아니라 커버리지에서 온다는 것을 이 한 줄이 말해준다.
